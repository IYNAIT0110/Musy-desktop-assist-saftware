# 安装、升级排错

## 已退出甚至重启，仍提示“STArra 无法关闭”

这句提示也可能来自旧版卸载失败，不代表一定有 STArra 后台进程。

已确认的一种情况：旧版安装在 `D:\musy`，新版安装包也放在 `D:\musy` 内运行。升级会调用旧版卸载器，把旧程序目录中的文件移到临时目录；正在运行的安装包本身不能被这样移走，因此升级失败。隔离测试已复现：普通文件可移动，正在运行的安装程序跨盘移动失败。

处理步骤：

1. 点「取消」，退出本次安装。
2. 将新版安装包移到桌面或“下载”文件夹。不要只在旧安装目录内换一个文件名。
3. 从新位置重新运行安装包。**软件安装位置仍可选原来的 `D:\musy`。**

无需删除旧安装目录、收藏、卷轴、项目关系或百宝匣，也不需要反复重启。

若安装包已经在安装目录外运行仍报错，则还需检查实际进程、权限、文件占用或旧版卸载错误，不能仅凭这句提示判断原因。重要数据请按[数据与迁移](数据与迁移.md)分别备份。

## 本地安装器改进（尚未重新发布）

安装器现会在调用旧版卸载器前，检查自身是否位于当前安装目录、已登记的当前用户或全机旧安装目录内。发现问题会直接说明如何移动安装包，并在更改软件文件前停止。检查包含子目录、大小写及结尾分隔符，不会误拦截名称相近的相邻目录。

Windows 隔离测试覆盖上述六种路径情况，测试标记数据保持不变。该防误操作改进目前只在本地安装包中，GitHub 已发布的 v0.2.1 附件未替换；现有 v0.2.1 安装包按上方步骤即可重试。
