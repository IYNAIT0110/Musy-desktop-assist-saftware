# 织梦台界面与操作改进方案

日期：2026-10-29。依据：当前 v0.3.2 的 ProjectWorkspace、UnifiedResourceBrowser、AgentProjectResults 及项目数据模型。本文保留原始设计建议；v0.3.3 已实现浏览/收集分离与文件看板，其他页面重排仍是规划。

优先级更新：用户提出应先设计项目文件看板。后续先按 [文件看板、版本与关系调研](织梦台文件看板-版本与关系设计调研-2026-10-29.md) 确认文件呈现、时间和关系，本文的总体页面重排后置。

## 定位

织梦台围绕一个项目回答三个问题：现在做到哪里、下一步做什么、需要哪些资料。每次打开优先帮助继续工作，同时保留项目资料整理能力。

## 现状与问题

| 现状 | 对使用的影响 | 改进方向 |
| --- | --- | --- |
| 点击项目标签直接调用全局项目选择 | 浏览其他项目也会改变小球之后的自动收集目标 | 分离“正在查看”和“正在收集到”；显式选择“设为工作项目”才改变全局目标 |
| 新建、状态、项目标签、撤销、导出、恢复共处一行 | 项目多时相互争夺宽度，主要操作不突出 | 保留横向布局；项目导航独立伸缩，整理及备份操作收进更多菜单 |
| 概览下紧接资料，再在末尾追加 Agent 成果 | 项目进展、资料与产出缺少清楚层级 | 使用概览、资料、任务、成果四个内容分区 |
| 资料条目以文本、路径和多按钮组成 | 图片、网站、提示词难以快速辨认，滚动成本高 | 类型对应预览，提供列表/网格；次要操作放右键菜单 |
| 每条资料都展示关联、取消关联等按钮 | 高频打开动作和整理动作权重接近 | 默认突出打开；悬停、右键或批量整理时显示其他动作 |
| 关联弹窗逐条点击即保存 | 大批关联要重复操作，取消含义容易误解 | 先选择、显示数量，确认后一次提交；取消不改变关系 |
| 继续工作只记录在织梦台成功打开/复制的资料 | 容易被理解成系统最近文件或完整工作历史 | 明确“最近在织梦台使用”；只显示真实记录，不推测进度 |
| 项目关联模型仅含网站、卷轴、素材；Agent 成果单独展示 | 笔记、任务和成果分散，项目上下文不完整 | 后续分别定义笔记/任务/成果的关联方式，复用已有身份和授权 |
| 专题文档仍有 v0.2.2 入口顺序等旧描述 | 与新版实际行为不一致 | 实施时同步专题指南、星砂内置说明和工作流 |

## 建议布局

保留现有横向项目导航和 STArra 配色、材质。第一轮不恢复左侧项目栏，不加入复杂后台式看板。

```text
项目选择 / 进行中·已归档                   ＋新建  ⋯
──────────────────────────────────────────
项目名                         设为工作项目 / 工作中
一句项目说明                 打开项目文件夹  ⋯

概览   资料   任务   成果
──────────────────────────────────────────
当前分区内容
```

全局搜索继续复用顶端搜索框，提示当前检索范围。搜索只检索当前分区的已接入数据；不把未接入的笔记或任务算进结果总数。

概览建议包含：最近在织梦台使用的资料、真实待办摘要、最近产出。资料与任务为空时提供对应的明确入口。没有数据的统计不生成虚构进度或百分比。

## 操作规则

1. 浏览项目不自动切换收集目标。查看项目与工作项目不同时，在项目标题旁明确显示收集目标，并提供“设为工作项目”。顶栏胶囊依旧管理全局工作项目。
2. 新建项目只要求名称，目录和说明可后补；提供明确的“同时设为工作项目”选项，显示其当前状态。
3. 项目资料打开后返回保留该项目的分区、搜索、筛选和滚动位置。切换项目不得把上个项目的异步结果覆盖到当前页。
4. 批量关联采用临时选择集，显示新增/取消数量和目标项目；提交前允许取消，提交失败保留选择。需对项目状态及源资料身份重新校验，避免部分成功却显示全部完成。
5. 卡片左键用于选择，双击打开，空格预览，右键提供上下文操作；网站直接打开应与现有模块习惯一致，最终按类型明确规定，避免同一动作意外执行删除。
6. 取消关联不删除原文件；归档保留资料；删除项目需要明确确认并支持原有撤销。归档、删除和恢复放入更多菜单，保留键盘可达性。
7. 缺失原件、回收区条目、资料库未连接分别提示；提供重新连接资料库或前往原模块处理，不只显示无法理解的禁用按钮。
8. 顶栏快捷收集开关与项目内收集状态共用一个真实状态。项目内不再叠加另一种普通复选框表达相同设置。

## 开发顺序

### 第一阶段：界面与信息层级

- 整理横向工具栏，项目标题、主要操作与更多菜单分层。
- 提取统一项目头部和资料条目组件，保留已有公开资料库入口。
- 调整空白、加载、失败与无搜索结果状态。
- 保留 Jelly Radio、Glide Select 和现有主题；动画用于切换与反馈，不延迟操作。
- 先接入概览/资料/成果，任务分区在真实数据接通后启用，避免空壳按钮。

### 第二阶段：核心操作

- 分离浏览项目与工作项目，明确新建、归档、删除后的收集目标。
- 批量关联与移除、选择取消、失败重试。
- 列表/网格、按项目记忆浏览状态，统一预览与右键操作。

### 第三阶段：项目工作闭环

- 将已有星砂笔记和星笺任务接入项目，避免复制出第二套任务或笔记库。
- Agent 成果归入统一成果视图，保留授权检查、来源、生成时间与失效状态。
- 在真实任务关联可用后提供概览摘要；如要加入阶段与里程碑，先定义其与任务的关系。

## 验收重点

- 开启项目 A 自动收集时，浏览项目 B 不改变收集到 A；显式设 B 为工作项目后才切换。
- 公共库、已归档项目、删除当前工作项目的边界行为明确。
- 多项目、长项目名与窄窗口不会把操作挤出或产生多层横向滚动。
- 批量关联取消无副作用，失败不丢选择，原件和其他项目关系保持。
- 空格预览退出后恢复选择与滚动位置，不卡住键盘焦点，不出现重复边框。
- 浅色、深色、玻璃、颗粒材质可读，减少动态效果模式可用。
- 原有项目数据与胶囊备份兼容，新增关联可迁移和恢复。

第一轮建议只推进第一阶段，同时先确定第二阶段的收集目标规则。设计确定后再修改项目数据逻辑，不在日常修改时自动发布。
