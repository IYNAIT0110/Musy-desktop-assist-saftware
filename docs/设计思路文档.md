# Musy 桌面悬窗助手 — 设计思路文档

> 面向设计工作者的桌面悬窗辅助工具
> 版本：v0.1（设计稿） | 日期：2026-10-23

---

## 1. 产品概述

### 1.1 一句话定位

一款常驻桌面的迷你悬窗助手，把设计工作者日常高频用到的「链接收藏、提示词收藏、软件快捷键、文本润色、模型库」等能力聚合到一个不打断工作流的悬浮窗里，随点随用、用完即走。

### 1.2 目标用户与痛点

| 目标用户 | 核心痛点 | 本工具对应解法 |
|---------|---------|--------------|
| 建筑/产品/游戏等设计工作者 | 常用素材网站、教程、灵感链接散落各处，找起来麻烦 | URL 链接收藏（分类 + 搜索） |
| AI 绘画/AIGC 使用者 | 提示词重复编写、效果难以回溯、缺乏沉淀 | 提示词收藏 + 效果预览图 |
| Rhino / SU / CAD 用户 | 快捷键记不住、软件间来回切换忘记命令 | 内置快捷键速查（可搜索） |
| 日常文案/汇报撰写者 | 文字表达不够专业、需要反复润色 | 文本润色（云端 AI） |
| 需要素材/模型资源的设计者 | 常用模型库散乱、本地/在线资源难统一管理 | 模型库（收藏 + 索引） |

### 1.3 核心设计原则

1. **不打断工作流**：迷你悬浮条常驻，一键呼出，用完即收，不占主屏工作区。
2. **本地优先、离线可用**：核心收藏/快捷键功能完全离线；AI 能力为可选增强。
3. **零配置迁移**：换电脑后导出一个备份文件即可完整恢复（见 §6 跨设备方案）。
4. **隐私可控**：所有数据存本地，AI 调用由用户自行配置 API Key，不经过第三方服务器。

## 2. 功能模块设计

### 2.1 双形态交互（全局框架）

| 形态 | 描述 | 触发方式 |
|------|------|---------|
| **迷你悬浮条** | 半透明窄条，常驻屏幕边缘，可拖拽、可贴边隐藏 | 启动即显示 |
| **展开完整窗口** | 完整功能界面，含左侧导航 + 右侧内容区 | 点击悬浮条 / 全局快捷键 |

悬浮条仅显示最常用的 4~5 个快捷入口（如：收藏、提示词、快捷键、润色、模型库），点击后展开对应模块。

### 2.2 功能模块清单

#### 模块一：URL 链接收藏

- **能力**：收藏网页链接，支持自定义标题、标签、分类、备注。
- **交互**：
  - 手动新增（粘贴 URL + 自动抓取标题）。
  - 一键收藏当前浏览内容（可选浏览器扩展，v1.1 再议）。
- **检索**：按关键词搜索 + 按标签/分类筛选。
- **打开**：点击调用系统默认浏览器打开。
- **数据结构**：`{ id, url, title, tags[], category, note, createdAt }`

#### 模块二：文生图提示词收藏

- **能力**：收藏提示词（prompt），并可附加效果预览图。
- **关键设计**：
  - 每条提示词可关联 **1~N 张预览图**（本地图片或网络图片链接）。
  - 支持「复制提示词」一键复制到剪贴板。
  - 支持中文/英文双语提示词字段。
- **字段**：`{ id, prompt, promptEn, negativePrompt, model, params, images[], tags[], createdAt }`
- **预览图存储**：图片存本地 `data/images/`，数据库存相对路径（见 §5）。

#### 模块三：软件快捷键指引

- **能力**：内置 Rhino、SketchUp（SU）、AutoCAD 等软件的快捷键速查表。
- **交互**：
  - 按软件切换（Tabs：Rhino / SU / CAD，可扩展）。
  - 按关键词搜索命令或快捷键。
  - 支持「自定义快捷键」——用户可添加/修改自己的快捷键映射。
- **数据来源**：
  - 内置默认快捷键库（随应用打包，离线可用）。
  - 用户自定义层（存本地，叠加在内置库之上）。

#### 模块四：文本润色

- **能力**：对选中的文字进行润色、改写、翻译、扩写/缩写等。
- **交互**：
  - 全局快捷方式（如 `Ctrl+Shift+Space`）呼出，自动读取剪贴板文本。
  - 选择润色风格（正式/简洁/口语化/学术等）。
  - 一键复制结果回剪贴板，直接粘贴回原应用。
- **实现**：调用云端 LLM API（OpenAI / DeepSeek 等），用户自填 Key（见 §5.4）。

#### 模块五：模型库

- **能力**：收藏/索引设计工作中用到的「模型、素材、组件」等资源。
- **形式**：
  - **本地文件**：记录文件路径 + 缩略图 + 标签（如材质、构件、家具）。
  - **在线资源**：记录下载链接 + 预览图。
- **交互**：卡片式浏览 + 分类筛选 + 搜索 + 一键打开所在文件夹/链接。
- **扩展**：v1.1 可接入 Sketchfab / 3D Warehouse 等在线模型站的搜索。

## 3. 技术架构

### 3.1 技术选型

| 层 | 技术 | 说明 |
|----|------|------|
| 桌面框架 | **Electron** | 跨平台（Win/macOS/Linux），开发效率高 |
| 前端 | **React + TypeScript + Vite** | 组件化开发，类型安全 |
| UI | 自研轻量组件 + Tailwind CSS | 控制体积，贴合悬浮窗审美 |
| 本地数据库 | **SQLite**（better-sqlite3） | 单文件数据库，无需服务，随包迁移 |
| 构建打包 | **electron-builder** | 产出安装包（NSIS/便携版） |
| AI 调用 | 直接 HTTPS 请求 OpenAI/DeepSeek 兼容 API | 无额外 SDK 依赖，用户填 Key |

### 3.2 进程架构

```
┌─────────────────────────────────────────────┐
│                 主进程 (Main)                │
│  - 窗口管理（悬浮条 + 主窗口）               │
│  - 数据持久化（SQLite 读写）                 │
│  - 文件系统操作（图片/模型路径）             │
│  - AI 请求转发（API Key 只存主进程）         │
└──────────────┬──────────────────────────────┘
               │  IPC（contextBridge，安全隔离）
┌──────────────▼──────────────────────────────┐
│              渲染进程 (Renderer)             │
│  - React UI（各功能模块）                    │
│  - 通过 preload 暴露的安全 API 与主进程通信   │
└─────────────────────────────────────────────┘
```

### 3.3 安全设计

- **contextIsolation 开启**、`nodeIntegration` 关闭。
- 所有主进程能力经 `preload` 通过 `contextBridge` 白名单暴露。
- API Key 仅存主进程（本地配置），渲染进程不直接持有。

## 5. 数据设计

### 5.1 数据存储方案

- 采用 **SQLite 单文件数据库**，存于用户数据目录。
- 用户数据目录（跨电脑后保持一致的用户目录）：
  - Windows：`%APPDATA%/Musy/`
  - macOS：`~/Library/Application Support/Musy/`
  - Linux：`~/.config/Musy/`
- 图片/预览图存 `data/images/`，数据库存相对路径，保证整目录迁移时路径不失效。

### 5.2 核心数据表

| 表名 | 用途 | 关键字段 |
|------|------|---------|
| `links` | URL 收藏 | id, url, title, tags, category, note, created_at |
| `prompts` | 提示词收藏 | id, prompt, prompt_en, negative, model, params, tags, created_at |
| `prompt_images` | 提示词预览图 | id, prompt_id, image_path, sort |
| `shortcuts` | 用户自定义快捷键 | id, software, command, keys, desc |
| `models` | 模型库 | id, name, type, path/url, thumb, tags, created_at |
| `settings` | 应用配置 | key, value（含 AI 配置、悬浮条位置等） |

### 5.3 导出 / 导入（跨设备迁移核心）

- **导出**：一键把 `musy.db` + `images/` 打包为 `.musy` 备份文件（本质是 zip）。
- **导入**：选择 `.musy` 文件，恢复数据库与图片。
- 内置快捷键库随应用打包，不参与导出（保证版本一致性）；仅用户自定义层参与导出。

### 5.4 AI 能力接入（文本润色）

- **方式**：直接调用 OpenAI 兼容接口，用户自行填写：
  - API Base URL（默认 `https://api.openai.com/v1`，支持 DeepSeek 等自定义）
  - API Key
  - 模型名（如 `gpt-4o-mini` / `deepseek-chat`）
- **封装**：主进程统一转发，前端只传「文本 + 润色风格」，不接触 Key。
- **容错**：无 Key / 网络失败时给出明确提示，不影响其它离线功能。

## 6. 跨电脑正常运行方案（核心约束）

这是本项目最关键的非功能需求，从三个层面保证：

### 6.1 可安装性（任何电脑都能装）

- 用 **electron-builder** 打包出标准安装包：
  - Windows：NSIS 安装器 + 便携版（zip 绿色版）。
  - 打包时把 Electron 运行时、Node 依赖、`better-sqlite3` 原生模块一并打入，**目标电脑无需预装任何环境**。
- 原生模块（better-sqlite3）针对目标平台预编译，避免「缺编译环境」问题。

### 6.2 可迁移性（数据随身走）

- 所有用户数据集中在用户数据目录（§5.1），一键导出 `.musy` 备份文件。
- 新电脑安装应用 → 导入备份 → 完整恢复收藏、提示词、预览图、模型库、自定义快捷键。

### 6.3 环境无关性（不依赖本机特殊配置）

- **不依赖系统环境变量**、不依赖全局安装的 Node/Python。
- AI 功能依赖网络 + 用户 Key，属于可选能力，缺失时优雅降级。
- 字体/图标全部随包内置，不依赖目标机已装字体。

## 7. UI / 交互设计

### 7.0 视觉设计规范（最终确定）

- **参考基准**：主要参考 **Raycast** 的设计元素与交互动画（命令面板、键盘优先、居中浮层、富结果列表）。
- **强调色**：沿用 Raycast 的**红橙发光色** `#FF6B35`（主）/ `#FF8A3D`（发光亮部），随焦点 bloom 扩散、渐变过渡。
- **底色**：暗色暖底（近黑带暖棕调，呼应红橙主题）：
  - 面板底 `#1A1410` → 卡片/输入框 `#251A12` → 选中项 `#2E1F14`
  - 文字：`#FFE8DB`（标题）/ `#B8A8A0`（次要）/ `#FFD9B8`（快捷键标签）
  - 描边：`#33251A`（默认）/ `#40291A`（hover）
- **圆角为主要视觉元素**：卡片 `18px`、搜索框 `26px`、浮层 `28px`，整体圆润柔和，无锐利直角。
- **交互动画丝滑流畅**：spring 缓动、弹跳入场（bounce-in）、悬浮浮动（float）。
- **可爱 + 情绪价值**：顶部可爱吉祥物（圆脸小人，随状态变化表情 happy/focus/sad/excited）、俏皮文案（「今天也辛苦啦！」）、腮红与微表情、庆祝动效。
- **字体**：等宽字体（monospace）渲染快捷键标签（Raycast 标志手法）。
- **布局**：单行文本布局，导航标签、标题栏不换行。

### 7.1 悬浮条（迷你形态）

- 半透明暗色窄条（磨砂玻璃 + 暗色暖底），可拖拽到屏幕任意边缘，支持贴边自动隐藏 + 鼠标悬停呼出。
- 常驻置顶（always-on-top），点击展开主窗口。
- 顶部吉祥物 + 5 个图标入口，图标 hover 轻微放大 + 发光选中态。

### 7.2 主窗口（展开形态）

- 顶部：吉祥物 + 问候语（俏皮文案）+ 圆角搜索框（带 ⌘K 快捷键标签）。
- 左侧竖向导航栏（收藏 / 提示词 / 快捷键 / 润色 / 模型库），选中项红橙发光。
- 右侧内容区按模块渲染，空状态展示吉祥物 + 可爱提示文案。
- 全局搜索框：跨模块模糊搜索（链接、提示词、快捷键、模型）。
- 布局遵循**单行风格**，导航标签、标题栏避免两行换行（用户既有偏好）。

### 7.3 关键交互细节

| 交互 | 设计 |
|------|------|
| 全局呼出 | 系统级快捷键（可自定义，如 `Alt+Space`） |
| 文本润色 | 全局快捷键读取剪贴板 → 呼出润色浮层 → 一键回填剪贴板 |
| 提示词复制 | 卡片上一键「复制提示词」按钮 |
| 预览图 | 网格缩略图，点击放大查看 |

## 8. 开发计划（里程碑）

| 阶段 | 内容 | 交付 |
|------|------|------|
| M1 骨架 | Electron + React + TS 初始化，双形态窗口 | 可运行的悬浮条 + 空主窗口 |

| M4 快捷键/模型库 | 内置快捷键库 + 自定义；模型库 | 离线功能齐备 |
| M5 润色 + 设置 | AI 润色 + API 配置 + 导出导入 | 全功能 + 可迁移 |

## 9. 风险与开放问题

| 风险/问题 | 影响 | 应对 |
|-----------|------|------|
| better-sqlite3 原生模块跨平台编译 | 打包/安装失败 | 用 electron-rebuild 预编译，或改选纯 JS 存储（如 lowdb）兜底 |
| 提示词预览图体积膨胀 | 备份文件过大 | 图片压缩 + 可选「仅索引不存储」 |
| 快捷键库数据准确性 | 用户体验 | 内置数据需人工校对，支持用户纠正 |
| AI 服务不可用 | 润色功能失效 | 优雅降级，不影响其它功能 |
| 悬浮窗与 CAD/Rhino 的置顶冲突 | 遮挡工作区 | 支持贴边隐藏 + 透明度调节 |
