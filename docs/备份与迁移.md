# 胶囊：STArra 备份与迁移

STArra 是 STArra 的新名称。现有数据目录、存储键和应用升级标识继续兼容，改名不会清空资料。适用 v0.3.0。

## 入口与完整备份

展开悬浮窗后，左侧功能栏中的「胶囊」图标提供备份与迁移。完整面板宽度从 760 扩展为 848 像素；屏幕较窄时按工作区限制宽度，小球尺寸不变，二级功能栏增宽至 450 像素以容纳八个入口。

1. 打开「胶囊」，选择「完整备份」。
2. 确认项目文件夹、百宝匣引用原文件、已配置数据路径三个选项。其他目录可用「添加其他文件夹」加入。
3. 点击「扫描并预览」，查看文件数量、容量、目录和缺失清单。
4. 若清单提示缺失、无权限或链接目录，先连接磁盘或修复权限并重新扫描；也可明确确认跳过后导出，届时这些文件不在备份中。
5. 点击「选择位置并打包」。建议保存到移动硬盘或另一块磁盘，避免同一磁盘故障同时丢失原件和备份。不能存入正在备份的源目录内部。

输出是 `STArra-日期-编号.starrapack` **文件夹**，无需解压。必须保留整个文件夹，不能只复制 manifest.json 或 state.json。此版本不提供压缩、定时备份和云端同步。

## 包含什么

- 应用内网站链接和收藏分组、卷轴与预览图、星砂便签与待办、项目资料关联、继续工作记录、界面外观和其他 `musy.*` 应用偏好。
- 当前连接的百宝匣目录，包括索引、自有封面、剪贴板素材及其他自有文件。
- 勾选的项目根目录及其子目录、当前资料库引用的外部原文件、已配置的数据保存路径。
- 手动添加的其他目录。
- 模型 API Key 默认包含，可取消勾选。备份中可能包含私人内容和密钥，妥善保管，勿上传公开仓库。

只发现**当前连接的资料库**。未连接的其他资料库应手动添加目录；恢复后可在「管理资料库」中选择恢复目录中的对应资料库。浏览器缓存、程序安装文件、其他软件的授权和安装环境不会打包。

符号链接、目录联接会跳过并列出提示，防止无限递归或意外打包库外内容。旧 `.starrapack` / `.musypack` 及未完成的临时备份不会递归打包。

## 按项目、最近修改或日期导出

- **最近修改**：默认过去七个日历日，可调整起止日期。
- **指定项目**：选择项目，默认不带整个自定义数据目录；可勾选「日期范围」进一步限制原文件。
- **日期范围**：按磁盘文件最后修改时间筛选，起止日均包含，使用当前电脑本地时间。

以上模式均保留完整应用记录和当前资料库的自有文件，**只有原文件受项目、日期及勾选范围限制**。例如导出最近七天的项目，早于范围的原文件不复制，但其资料记录仍保留；迁移后可能需要重新定位这些原件。指定项目会打包该项目文件夹与当前库内关联该项目的引用原件。

附加目录受日期筛选；当前资料库目录始终完整复制。嵌套目录共用一份输出，避免重复复制同一路径。扫描后调整任何范围都必须重新扫描。

## 换电脑继续工作

1. 安装 STArra，将整个 `.starrapack` 文件夹复制到新电脑。
2. 打开「胶囊」入口，选择「从备份恢复…」，选择该文件夹。
3. 确认恢复并选择新工作目录的保存位置，确保磁盘空间足够。
4. 程序逐文件校验并复制，生成新的 `STArra-workspace-编号` 工作目录，重建已打包的项目、资料库与数据保存路径。
5. 恢复完成后自动重启，使用新配置继续工作。旧电脑盘符不需要在新电脑存在。

恢复会创建独立应用配置，**当前配置和原文件会保留**。已排除或缺失的原件不会凭空补齐。Rhino、CAD、SketchUp、Photoshop、Office 等软件需要在新电脑单独安装，系统缩略图能力也取决于当地软件环境。

恢复目录在检查通过前先写入临时目录。失败或取消不会激活新配置；少量已完成复制的恢复目录可能保留供排查，但不会被当成当前工作数据。

## 校验与恢复点

每个文件保存 SHA-256 校验值。复制时检查源文件大小和修改时间，并校验输出；恢复时再次检查内容。若文件在打包期间被修改，操作停止，请关闭编辑该文件的软件后重新扫描。

`manifest.json` 保存打包范围、原路径、文件校验值和缺失提示；`state.json` 保存完整应用记录。不要手动修改。取消后不生成标为完成的备份。

恢复的新配置位于现有应用数据根目录的 `backup-profiles/编号`，`backup-profile.json` 记录当前与上一个配置位置。首次迁移初始化失败会自动切回上一个配置。若需要人工排查，先退出程序并备份整个应用数据根目录，再联系反馈渠道；不要删除旧配置或原文件。

历史 JSON / `.musyprojects` 索引备份继续使用原入口。它们主要包含记录，不能代替携带原文件的 `.starrapack` 备份。
