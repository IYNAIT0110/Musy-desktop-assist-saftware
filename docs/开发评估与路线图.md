# Musy 开发评估与路线图

> 2026-10-26 / v0.2.0 文档校准：这是开发阶段的历史评估。v0.2.0 已交付百宝匣 P0、剪贴板/小球收集、轻预览/拖出、卷轴卡牌、外观与交互增强。点睛笔、密钥加密、卷轴磁盘化、完整原件导出等仍待推进。当前功能以使用指南为准。 [使用指南](使用指南.md) · [发布说明](releases/v0.2.0.md)

> 评估日期：2026-10-24
> 依据：本地 v0.1.4 源码、设计思路文档、使用指南与发布脚本。本文是开发决策报告，不代表已完成用户测试或跨电脑实测。

## 一、结论

Musy 的价值是让建筑及其他设计工作者在当前软件旁边，快速保存、找到并复用资料。产品应坚持四项原始原则：**少打断工作、本地离线可用、数据可迁移、隐私可控**。现有的悬浮球、链接收藏、提示词工作区和快捷键速查已形成可用骨架。下一阶段最重要的工作不是继续增加入口，而是把“保存—查找—复用—换机恢复”做可靠、做顺手。

建议按这个顺序投入：① 数据安全与备份；② 减少采集和检索步骤；③ 完成与设计工作直接相关的润色、模型索引；④ 经过实际使用数据验证后，再考虑浏览器扩展、跨平台等范围更大的工作。

## 二、现状与原设计的差距

| 领域 | 当前源码所见 | 原设计目标 / 判断 |
| --- | --- | --- |
| 桌面形态 | 悬浮球、胶囊、主面板、提示词工作区已经实现；可拖动、打开模块 | “随点随用”基本成立，但全局呼出快捷键、贴边自动隐藏、透明度设置尚未找到实现 |
| 链接 | 内置网站与事务所、剪贴板收藏、分组、拖拽排序、搜索、favicon 缓存与内置兜底 | 已能用于日常收藏；缺少编辑网址/标题/备注、删除撤销、批量整理与失效链接检查 |
| 提示词 | 添加、编辑、标签、搜索、图片、父子项、复制、可选 AI 改写/翻译 | 功能较完整；图片以 data URI 放在 `localStorage`，容量与迁移风险高；原设计提出的多图、模型参数结构化字段尚未实现 |
| 快捷键 | Rhino、SketchUp、AutoCAD 内置速查和搜索 | 离线可用；原设计中的用户自定义快捷键层没有实现，需要校验不同软件版本/键位配置 |
| 文本润色与模型库 | 导航和空状态已有，独立功能未实现 | 属于原设计的核心模块，宜在数据层稳定后分阶段交付 |
| 数据与迁移 | `localStorage` 为主存储；选定文件夹后写 `musy-data.json`，可导入 JSON | 与原设计的 SQLite + 独立图片文件 + 完整备份包不同；当前配置、图片和未来模型文件的迁移边界不够清楚 |
| AI 与隐私 | 用户配置兼容接口，主进程发送请求；API Key 明文写入渲染进程 `localStorage` | 与设计文档“Key 仅存主进程”不一致，应优先修正；AI 必须保持可选 |
| 交付验证 | Windows 安装包、便携版及 CI 安装启动冒烟检查 | 已覆盖“能启动”；缺少真实数据的导入导出、升级兼容、离线使用、不同分辨率/DPI 的验收 |

## 三、应先完善的功能与质量问题

### P0：确保用户数据真实保存、完整恢复

1. **写入成功必须有真实结果。** 当前 `writeLS()` 会返回失败，但链接的 `setLinks()` 丢弃返回值，`addLink()` 仍会返回成功；新增分组等操作也没有统一反馈。遇到配额或磁盘异常时，界面可能提示成功而数据没有落下。将数据操作改为显式成功/失败，并在失败时保持界面原状态。
2. **将图片从 `localStorage` 搬出。** 源码已注明 base64 预览图可能触及约 5–10 MB 的浏览器配额。采用应用数据目录中的独立图片文件，元数据用事务式数据库或带版本的持久化文件保存；迁移现有数据时先备份、再转换、最后验证数量与校验值。
3. **把备份变成可验证的产品功能。** 目前文件夹备份是可选的异步调用，界面没有明确告知每次写盘是否成功；主进程虽用队列及临时文件替换，渲染端仍以 `void syncToDisk()` 忽略结果。应显示最近成功备份时间、失败原因，提供手动导出、预览备份内容、恢复后对账和回滚点。
4. **明确“完整迁移”的范围。** 备份至少应覆盖链接、分组、提示词、预览图、用户自定义快捷键、模型索引及必要设置；API Key 默认不进可移植备份，由用户在新电脑重新填写。导入时做版本迁移、字段和体积校验，避免部分写入或恶意/损坏数据导致库异常。

**验收标准：** 模拟存储满、路径失效、写盘中断时，界面不报假成功；用含图片与自定义数据的备份在全新 Windows 账户中恢复，条目数、图片可读性和关键字段完全一致。

### P0：保护 API Key 并让网络行为可见

`ModelSettings.tsx` 当前把包含 `apiKey` 的完整配置 JSON 写进渲染进程 `localStorage`。建议将 Key 经主进程保存到系统保护的本机存储，并只向渲染进程返回“已配置/未配置”；保留清除 Key 与连接测试。Electron 官方提供使用系统加密能力的 [`safeStorage`](https://www.electronjs.org/docs/latest/api/safe-storage)，实现时需按项目所用 Electron 版本核对 API。发往第三方模型的内容在用户点击前应标明接收方、文本范围及是否会收费。

**验收标准：** 开发者工具、备份 JSON 和普通设置对象中读不到明文 Key；离线与错误 Key 均有明确提示，收藏等离线功能不受影响。

### P1：把“快速收藏”变成可持续整理

- 支持编辑标题、网址、备注/标签，操作后立即可搜索；删除提供短时撤销。现有 `LinkItem` 有标题和简介，但 UI 主要支持新增、分组、排序与删除。
- 加入批量移动、去重预览与浏览器书签 HTML 导入；可先仅导入文件，不急于开发浏览器扩展。
- 网站图标沿用“站点声明 → 常见路径 → 服务兜底 → 字标”的现有策略，增加手动替换与刷新入口，失败不应阻碍收藏。
- 对失效链接采用用户主动触发检查，展示重定向和检测时间，避免启动时批量请求影响速度或隐私。

**验收标准：** 从复制网址到可检索的收藏不超过两步；能一次整理几十条旧收藏；误删可撤销；离线时仍能查找已有收藏。

### P1：真正实现“一键找到并复用”

- 增加可自定义的全局呼出快捷键，注册失败时提示冲突并允许改键；输入焦点自动进入搜索。Electron 的 [`globalShortcut`](https://www.electronjs.org/docs/latest/api/global-shortcut) 可用作实现依据。
- 搜索覆盖链接标题/网址/备注、提示词正文/标签、快捷键命令；清楚标识结果来自哪个模块，并支持键盘上下选择、回车打开/复制。
- 快捷键条目显示适用软件版本、系统和来源；用户可添加自己的映射，并与内置数据区分，避免升级覆盖个人配置。
- 为悬浮球增加“贴边隐藏/始终显示/暂停置顶”设置，尤其照顾 CAD、Rhino 的绘图空间。

**验收标准：** 从正在工作的设计软件中，呼出并找到目标资料、完成打开或复制的流程不依赖鼠标；多显示器、缩放 100%/150%/200% 下窗口不越界。

### P1：交付稳定性

在现有 CI 安装启动冒烟检查之外，加入带真实样本的**升级、备份恢复、离线启动、重复启动**检查；为数据迁移与导入校验写自动化测试。发布前在干净 Windows 10/11 x64 环境各做安装版和便携版验证，记录结果。Electron 官方[安全检查清单](https://www.electronjs.org/docs/latest/tutorial/security)可作为窗口、导航、外链和版本维护的复核依据。当前只做代码与文档评估，不能据此断言所有电脑均可正常安装使用。

## 四、面向开发初衷的新功能

| 功能 | 对设计工作者的具体价值 | 最小可用版本 | 建议阶段 |
| --- | --- | --- | --- |
| **项目资料夹** | 将一个项目的链接、提示词、模型文件引用放在一起，减少跨模块反复查找 | 项目名称、关联已有条目、项目内搜索、打包导出；不复制原文件 | 第二阶段 |
| **文本润色** | 改写设计说明、汇报摘要、图纸注释，减少从绘图软件切去网页聊天 | 粘贴/读取剪贴板 → 选择“简洁、汇报、翻译” → 结果对照与复制；用户主动触发 AI | 第二阶段 |
| **本地模型/材质索引** | 快速定位散落的 `.skp`、`.3dm`、材质贴图等资源 | 选文件夹建索引、标签、预览、打开文件位置、路径失效提示；记录来源/授权信息 | 第二至第三阶段 |
| **轻量参考板** | 临时并排查看少量参考图或链接，同时保持绘图窗口可见 | 从已有资料固定 3–6 张图/链接，支持置顶与透明度 | 第三阶段，先做用户验证 |
| **工作流模板** | 一次调用常用资料组合，例如“方案汇报”所需网站、提示词和快捷键 | 用户自建模板；点击后打开资料夹并提供复制动作 | 项目资料夹验证后 |

项目资料夹是最符合 Musy 定位的差异化方向：它连接现有模块，但无需先做庞大的云端素材平台。模型库应从**索引本地资源**开始，避免复制大文件导致空间和备份负担。提示词数据继续由用户自己建立；不预装“效果图提示词”数据集。

## 五、外部产品给我们的启发

- [Raycast 的 Quicklinks 与 Snippets](https://manual.raycast.com/new-in-v2)说明“键盘呼出、搜索、执行”可以成为统一入口。Musy 应借鉴动作路径，而不是复制一整套通用启动器。
- [PureRef 的官方功能说明](https://www.pureref.com/handbook/features/)展示了置顶、透明度、分组如何服务创作过程；Musy 可先验证小型参考板是否有价值。
- [Eagle 的官方整理说明](https://en.eagle.cool/support/desktop/organize)将标签、文件夹、智能文件夹和相似重复项用于资产整理。Musy 的模型库可以借鉴标签与失效路径管理，但应保持轻量。

以上是竞品启发，不表示 Musy 已具备这些能力，也不建议一次性照搬。

## 六、建议实施顺序与交付门槛

| 阶段 | 时间估计* | 范围 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| A. 数据底座 | 2–3 周 | 保存结果反馈、图片迁移、完整备份恢复、Key 安全存储 | 损坏/断电模拟和新账户恢复通过；无明文 Key 泄露 |
| B. 高频体验 | 2–3 周 | 链接编辑/撤销/批量导入、统一搜索、全局呼出、自定义快捷键 | 5 位目标用户完成“采集—查找—复用”任务，无阻断问题 |
| C. 原设计功能 | 3–5 周 | 文本润色、本地模型索引、项目资料夹的最小版本 | 离线基本功能可用；大目录索引不明显拖慢启动；导出覆盖新增数据 |
| D. 验证后扩展 | 另行评估 | 参考板、浏览器扩展、macOS、更多集成 | 先获得真实使用证据，再决定投入 |

\*时间是单人开发的粗略排期假设，取决于数据迁移复杂度与测试环境，不是交付承诺。每阶段都保留安装版和便携版验证。暂不优先做账号体系、强制云同步、自动读取屏幕内容或大规模在线素材聚合：这些会增加维护与隐私成本，也偏离“随点随用”的定位。

## 七、衡量是否真的变好

1. **可靠性：** 100% 的保存失败有可见反馈；迁移样本恢复后条目与图片校验一致；每次备份显示成功时间。
2. **效率：** 记录目标用户从“看到网址/想到素材”到“保存完成”的步骤和耗时，以及从设计软件中找到并复制资料的耗时；与当前版本同任务比较。
3. **打扰程度：** 观察悬浮球遮挡、误触、快捷键冲突以及多显示器越界的发生次数。
4. **采用情况：** 在征得用户同意且不上传隐私内容的前提下，优先通过访谈或本地统计观察链接、提示词、快捷键和未来项目资料夹的实际使用，而不是仅看功能数量。

## 八、本次评估边界

本次结论来自静态检查，不涉及修改产品功能、发布版本或上传 GitHub。当前环境的命令行未找到 `npm`，因此未完成本轮 TypeScript 检查和运行测试；报告把运行期表现作为待验证事项。设计文档包含规划内容，与现行实现不一致的地方，均按当前源码判断。
