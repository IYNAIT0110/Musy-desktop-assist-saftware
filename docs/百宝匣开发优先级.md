# 百宝匣开发优先级与交付范围

> 2026-10-26 / v0.2.0 文档校准：发布状态：v0.2.0 已完成 P0、P1 顺序 2（BB-11）及顺序 7（BB-16）。其余 P1/P2/P3 项目仍为计划，不因本次发布而视为完成。原生预览已有部分嵌入缩略图提取，不等于完成全部 3D 预览。 [使用指南](使用指南.md) · [发布说明](releases/v0.2.0.md)

日期：2026-10-25。状态：P0 功能已实现，实际交付与验收边界见 [P0 使用与交付说明](百宝匣P0使用与交付.md)。P1 的 BB-11、BB-16 已在本地实现，见 [P1 收集与复用说明](百宝匣P1收集与复用.md)，外部软件实际拖放兼容性待手动验收。下列“当前起点”保留为开发前基线，其余 P1–P3 仍为开发建议。适用项目：Musy 本地 Windows 桌面版。

## 1. 建议先做什么

**先把百宝匣做成设计工作者随手可用的本地素材索引：把模型、材质和参考图收进目录，快速找到，打开或拿去使用。**

建议开发顺序：

**可靠保存 → 本地导入 → 卡片与封面 → 分类搜索 → 打开复用 → 备份与路径修复 → 批量采集与整理 → 高级预览与 AI。**

首版完成后，用户应能将一个真实项目的资料目录加入百宝匣，给模型补封面、分组和标签，重启后搜到并打开文件；换盘或换电脑时，能知道哪些文件随备份迁移、哪些需要重新定位。

本计划延续 Musy 的开发初衷：常驻但少打扰、离线可用、用户掌握数据、适合建筑及其他设计工作。优先服务 `.skp`、`.3dm` 等模型和材质贴图的日常查找，再逐步扩大素材种类。

## 2. 当前起点与范围边界

### 当前源码确认的情况

| 项目 | 当前状态 | 对开发的影响 |
| --- | --- | --- |
| 百宝匣入口 | 已有名称、图标和空状态 | 可以沿用现有导航；仍需新增真正的素材面板 |

以下是官方功能事实与百宝匣的开发取舍，右侧均为本项目建议。

| Eagle 的做法 | 对百宝匣的启发 | 优先级 |
| --- | --- | --- |
| 资源库、导入导出和备份 | 先定义素材记录、原文件和封面各自存在哪里，恢复时怎样对账 | P0 |
| 文件夹、标签、评分和搜索 | 分类必须能帮助找回素材，首版先做分组、标签和关键词检索 | P0；评分后置 |

| 浏览器拖拽、批量采集、截图 | 收集操作尽量短；先支持本地文件，之后再接剪贴板、悬浮球和网页采集 | P1–P2 |

| AI 图像相似检索、文本语义检索 | 在元数据和索引可靠后，再投入模型下载、索引构建和硬件适配 | P2 |
| Web API、插件 | 后续可连接已有 Eagle 库或开放扩展接口 | P2–P3 |

来源：[Eagle 桌面功能目录](https://en.eagle.cool/support/desktop)、[浏览器扩展](https://en.eagle.cool/extensions)、[AI Search 说明](https://en.eagle.cool/blog/post/eagle-plugin-ai-search)、[Web API](https://developer.eagle.cool/web-api)。完整竞品清单见 [Eagle 功能调研](Eagle功能与开源情况调研.md)。

## 4. 优先级定义

| 等级 | 含义 | 交付原则 |
| --- | --- | --- |
| P0 | 首个可用版必须具备 | 任何一项缺失，都可能造成资料丢失、找不到或不能复用 |
| P1 | 首版可用后的效率增强 | 优先减少高频操作，并支持素材量增长 |
| P2 | 需要技术验证的能力 | 依赖格式兼容、采集适配、模型索引或外部软件 |
| P3 | 有使用证据后再考虑 | 投入大或维护面广，暂不进入近期排期 |

表中 S/M/L 为相对工作量：S 为单个局部能力，M 涉及多个界面或进程，L 涉及存储、后台任务或格式兼容。它们不是工期承诺；正式排期应在数据底座和文件样本验证后估算。

## 5. P0：首个可用版

以下编号也可直接用作后续开发任务编号。

| 编号 | 工作项 | 具体范围 | 依赖 / 工作量 | 验收标准 |
| --- | --- | --- | --- | --- |
| BB-01 | 独立素材存储 | 主进程管理素材元数据；封面与缓存放独立文件目录；保存返回真实成功/失败；建立数据版本与恢复点 | 起点 / L | 重启不丢记录；写入失败不显示成功；封面不以 base64 放入 `localStorage` |
| BB-02 | 资料库与文件模式 | 用户选择资料库目录；首版对已有模型/素材默认建立路径引用，明确显示“引用”；记录资料根目录，支持批量重新定位 | BB-01 / M | 加入大模型不会暗中复制整份文件；断开的硬盘或路径可见地标为缺失；重连能恢复 |
| BB-03 | 本地导入 | 文件选择和拖入面板；可选择目录递归导入；后台分批处理，支持取消、失败清单和重试 | BB-01、02 / L | 取消后已成功条目保留，未完成项状态明确；坏文件不阻塞整批；不会每次启动重新扫描全部目录 |
| BB-04 | 素材卡片与封面 | 图片缩略图；模型和未知格式采用格式图标，支持用户指定图片封面；按需加载缩略图 | BB-03 / M | 模型即使没有原生预览也能被收藏和找到；大图不全尺寸加载进网格；封面失败可重试 |
| BB-05 | 基础分类与资料字段 | 新建/改名/删除分组、分组排序、批量归组；标签、显示名称、备注、来源 URL、作者及授权备注 | BB-01、03 / M | 同名冲突有反馈；删分组不删文件；名称、备注、标签修改后可检索；授权字段保持用户填写内容 |
| BB-06 | 检索与筛选 | 名称、原文件名、标签和备注搜索；按分组、类型筛选；按导入时间或名称排序；保留上次筛选 | BB-04、05 / M | 搜索覆盖所有已导入记录；筛选可一键清空；滚动与切换分组不会挤走导入按钮 |
| BB-07 | 打开与复用 | 双击用系统默认应用打开；打开所在文件夹；复制文件路径；记录最近使用；缺失时进入重新定位流程 | BB-02、04 / M | `.skp`、`.3dm` 等可通过已安装的软件打开；无默认应用和文件缺失分别提示；未安装设计软件仍可浏览记录 |
| BB-08 | 移除与撤销 | 从素材库移除进入百宝匣回收区，可恢复；默认不操作引用文件的原件；明确区分移除条目和删除磁盘文件 | BB-01、02 / M | 误移除可恢复，标签和封面不丢；移除引用记录后原文件仍在原位置 |
| BB-09 | 备份、恢复与重新关联 | 导出元数据、分组标签和自有封面；列出外部引用文件数量及根目录；恢复前显示摘要，保留恢复点；支持更换引用根目录 | BB-01–08 / L | 用新目录恢复后条目、分类和封面对得上；外部原件未随包迁移时明确列出缺失项，不能报告“全部恢复完成” |

### 首版格式承诺

“能收进百宝匣”“能显示缩略图”“能在内部交互预览”分别验收，不能合并宣传为“支持某格式”。

| 文件类型 | P0 支持范围 | 后续增强 |
| --- | --- | --- |
| JPG、PNG、WebP 参考图和贴图 | 索引、缩略图、查看原图、外部打开 | 颜色检索、比较、裁剪等 |
| SKP、3DM | 索引、标签、自定义封面、外部打开 | 通过可用的系统缩略图或专项适配生成封面 |
| DWG、BLEND、MAX 等设计源文件 | 作为通用文件索引、格式占位图和外部打开；使用用户提供的样本验证 | 按格式分别做技术可行性验证 |
| PDF、视频、字体、压缩包等 | 可作为普通文件记录，首版不承诺内部预览 | PDF/媒体预览、字体试用和压缩包内容等按需求扩展 |

模型贴图、外部参照和材质可能分布在多个文件中。首版保留目录关系和位置入口；对“连同贴图一键迁移/交付”暂不作承诺，后续通过项目资源包解决。

## 6. P1：让每天使用更省事

| 顺序 | 编号 | 工作项 | 为什么排在这里 | 前置条件 |
| --- | --- | --- | --- | --- |
| 1 | BB-10 | 批量编辑、移动、标签与重命名 | 素材导入后会很快产生整理需求；先批量改显示名，磁盘原件改名作为另一个明确动作 | P0 数据与撤销 |
| 2 | BB-11 | 剪贴板图片入库、拖到小球收集 | 延续 Musy 的无感交互；用户拖入时才展开接收区，给简短成功反馈 | 自有文件存储、任务反馈 |
| 3 | BB-12 | 托管副本与完整导出包 | 对常用素材提供“复制到资料库”，并可选择将引用原件纳入迁移包；先展示空间估算 | P0 引用模式与备份；磁盘空间检查 |
| 4 | BB-13 | 完全重复文件识别 | 用内容哈希识别相同文件；扫描在后台进行，先给结果供用户决定，不能按同名自动删除 | 导入任务队列、回收机制 |
| 5 | BB-14 | 多级分组、智能资料夹与常用筛选 | 用已有类型、标签、日期、评分等条件自动汇集；规则目录不复制原件 | 分类及筛选字段稳定 |
| 6 | BB-15 | 常用素材与项目资料夹 | 关联百宝匣文件、传送门链接、卷轴提示词；快速找回当前项目所需资料 | 稳定条目 ID、跨模块关联模型 |
| 7 | BB-16 | 轻预览与拖出复用 | 空格查看、图片并排参考、拖出真实文件；按 Windows 资源管理器、SU、Rhino 等目标分别验收 | P0 打开流程和文件解析边界 |

本轮交付：顺序 2 与 7 的功能已接入。BB-11 包含手动剪贴板入库、小球按需接收、一次批次反馈和失败重试；BB-16 包含独立空格预览、缩放/置顶、2–4 张图片并排参考和真实文件拖出。资源管理器、SU、Rhino 的真实接收效果按目标分别保留人工验收，不能据接口测试宣称所有目标兼容。

BB-11 的剪贴板行为建议：图片由用户点击或拖入时保存；如提供自动提醒，应可关闭、去重和限频。不要持续为每次复制弹窗。多选导入只反馈一次批次结果。

BB-12 的完整资源包需要区分“单文件”和“带依赖的项目目录”。迁移 SKP/3DM 本体不代表已经收齐所有外部资源。打包目录时保留相对结构，说明所包含的文件，避免遗漏被掩盖。

## 7. P2：技术验证后再排期

| 编号 | 工作项 | 主要价值 | 放到后面的原因与试验门槛 |
| --- | --- | --- | --- |
| BB-17 | 原生模型封面和 3D 预览 | 更直观挑选模型 | 专有格式差异大；先验证用户真实的 SKP/3DM 文件、版本、体积和许可条件。系统缩略图不可用时保留手动封面；不因缺少某个设计软件导致应用无法启动 |
| BB-18 | 自动监控目录 | 下载后自动入库 | 先解决取消、增量更新、文件仍在写入和重复导入；先本地目录，再考虑移动盘、NAS |
| BB-19 | 网页采集 | 减少从网站到资料库的步骤 | 浏览器扩展和站点变化带来维护；先做来源 URL 与明确的图片保存动作，再验证批量采集及高清图规则 |
| BB-20 | 颜色检索、相似图与 AI 标签 | 查找只记得外观的素材 | 先有足够资料再衡量收益；相似度不能当作同一文件；AI 标签应先预览、可撤销 |
| BB-21 | 自然语言检索 | 用描述找素材 | 先保证名称/备注/标签质量；明确是检索文字元数据还是直接理解图像，分别设评估样本 |
| BB-22 | Eagle 连接器 | 已有 Eagle 用户可从 Musy 快速查找、收藏或打开已有资料 | 通过公开 API 连接，先做只读查找及定位；需 Eagle 运行和满足接口版本。连接失败不影响百宝匣本地功能 |

Eagle 官方将本地图片相似检索与基于已有文字元数据的自然语言检索分开说明，值得百宝匣借鉴。不要把“关键词换成自然语言输入框”就当成图像理解功能。来源：[Eagle AI Search](https://en.eagle.cool/blog/post/eagle-plugin-ai-search)。

Eagle Web API V2 支持从外部应用通过本地 HTTP 接口访问库，要求 Eagle 4.0 Build 21 或以上且应用正在运行。BB-22 可据此验证，不直接修改 Eagle 库内部文件。来源：[官方 Web API](https://developer.eagle.cool/web-api)。

## 8. P3：有明确需求后再做

- 自建账号、云存储、多端实时同步和团队权限体系：需要解决冲突、容量、账户和长期服务成本。
- 全量格式预览、跨格式转换和在线模型商城：范围大，优先由独立适配器或外部工具承担。
- 插件中心、公开插件运行时：先稳定本项目的数据与文件接口，再开放第三方扩展。
- 大型参考画布、在线协作审阅、自动生成完整模型：需单独验证用户需求与开发成本。
- 自动上传全部素材分析、自动删除所谓相似素材、后台改动原件目录：不设为默认行为。

## 9. 开发实现顺序与依赖

| 里程碑 | 实施任务 | 本阶段交付 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| M0 技术验证 | BB-01、02 的存储与路径样机；准备真实文件样本 | 数据格式、失败恢复方案、引用文件与自有封面的目录规则 | 数据重启可读，缺失根目录不会清空已有索引 |
| M1 核心闭环 | BB-03–07 | 百宝匣面板：导入、卡片、分类、搜索、外部打开 | 可用一个真实项目走完“存入—找到—打开” |
| M2 首版交付 | BB-08、09，加导入任务恢复与安装包适配 | 可撤销、可备份、可恢复的 P0 版本 | P0 验收项全部通过，再视为首个可用版 |
| M3 高频效率 | BB-10–16 按实际使用排序 | 批量整理、快捷收集、托管迁移、智能资料夹和项目关联 | 用真实使用记录证明减少步骤，数据和恢复逻辑覆盖新字段 |
| M4 深度扩展 | BB-17–22 中完成验证的项 | 每次只交付一个有明确边界的增强能力 | 有格式样本、检索评估或 API 验证结果；失败时能回到基础功能 |

主依赖：`BB-01 → BB-02/03 → BB-04/05 → BB-06/07 → BB-08/09`。采集依赖存储、完整备份依赖文件模式、智能资料夹依赖字段、AI 检索依赖稳定索引。

### 建议的数据底座

- 为百宝匣建立主进程素材仓库服务，优先验证 SQLite 元数据索引；是否采用原生绑定，以当前 Electron 安装包可打包、可升级为门槛。此选择是拟议方案，尚未接入。
- 短期保持已有链接、卷轴数据可用，新增素材仓库独立接入；全应用数据迁移另列任务，避免百宝匣开发同时改写所有旧数据。
- 资料库采用 `manifest + 元数据索引 + covers + cache`。引用原件保留在原位置；托管副本后续放在 `originals`，并存相对路径。
- 核心记录至少有 `id、displayName、originalName、kind、storageMode、rootId、relativePath、coverPath、groupIds、tags、note、sourceUrl、author、licenseNote、createdAt、updatedAt、availability`。大小、修改时间、哈希和缩略图状态按需补充。
- 封面是自有资料，缩略图是可重建缓存，外部引用是用户原件，三者分别管理；备份不能只保存数据库而漏掉用户封面。
- 导入、哈希和缩略图按后台队列处理，渲染进程只请求当前可见页；扫描不阻塞启动。数据写入与后台任务状态都要能恢复。
- 文件系统操作经 preload 白名单接口进入主进程；外链和本地打开采用不同接口。文件内容不作为可执行网页运行，未知格式交给外部应用。

## 10. 界面与交互约束

1. **小面板内完成高频动作。** 顶部固定“导入”；左栏分组单独滚动；右侧卡片按需加载，底部工具不挤占列表。沿用已有分组长按排序习惯。
2. **详情按需展开。** 卡片显示封面、名称和类型；打开详情后再显示标签、来源、授权备注、路径和按钮。文件名称可截断，悬停能看到完整名称。
3. **状态必须有区别。** 空库提供导入入口；无搜索结果提供清除筛选；导入中显示数量进度与取消；路径失效提供定位；封面失败保留占位与重试。
4. **重要动作给明确反馈。** 保存完成后才提示已收藏；批次结束列出成功、重复、失败和跳过数量；文件重复需要用户决定如何处理。
5. **键盘与鼠标都能用。** 搜索聚焦、上下选择、Enter 打开、Esc 关闭预览；快捷键冲突先反馈，不能抢走设计软件中的关键输入。
6. **小球保持克制。** 一批导入结束只给一次反馈；不逐文件发气泡；下载或扫描不会把正在绘图的窗口强行切走。

## 12. 本轮开发决策

近期先交付 P0 的“本地模型与素材索引”。最先实现的三件事是 **BB-01 独立存储、BB-02 文件模式、BB-03 本地导入**。它们完成后，再做卡片、分类检索和打开，最后以撤销与备份补齐首版交付门槛。

先用用户自己的一个项目目录验证流程；默认不附带用户素材或效果图提示词。所有界面文字、图标和导航继续沿用当前 Musy 风格。

本轮已按 P0 实现独立 JSON 索引、原子写入与快照恢复，未引入原生 SQLite 绑定。封面独立存盘；具体实现、测试记录和后续人工验收范围见 [交付说明](百宝匣P0使用与交付.md)。开发时仅本地验收；现已纳入 v0.2.0 发布范围。
